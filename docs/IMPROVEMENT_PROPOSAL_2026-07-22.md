## 提案A：検索流入の基盤（最優先・費用ゼロ）

### A-1. Search Console の運用開始【人間タスク＋軽作業】
- 所有権確認は済んでいる。**sitemap送信とインデックス状況の確認が未着手**（docs/LIGHT_TASKS.md 記載）
- 268記事を量産しても、インデックスされなければ流入はゼロ。すべての施策の前提
- 手順: Search Console → サイトマップ → `https://topica-law.com/sitemap-index.xml` を送信 → 数日後にカバレッジ確認
- 以後は月次で「表示回数・CTR・掲載順位」を見て、CTRが低いページの seoTitle/description を改善するループを回す

### A-2. Phase 5：判例個別ページ（/hanrei/）【SEO効果・独自性ともに最大】
- 今回の記事量産で **courts.go.jp で事件番号・出典・裁判要旨まで照合済みの判例台帳が約300件規模** で docs/CONTENT_PLAN.md に蓄積されている。これは他サイトが簡単に真似できない一次資料ベースの資産
- 「最決平29年4月26日」「GPS捜査 判例」「誤振込 詐欺 判例」のような判例名検索・論点×判例検索の受け皿を作る
- 台帳→frontmatter（裁判所・判決日・出典・通称・関連トピック・関連条文）への変換は機械的にでき、本文（事案/判旨/意義）はワーカー執筆で量産可能。既存記事と相互リンクして内部リンク網を強化
- 初期対象: 台帳から著名判例50件程度 → 反応を見て拡大

### A-3. Phase 4：用語集の1用語1ページ化
- 「善意 悪意 法律用語」「訴因とは」等の「〜とは」ロングテールの受け皿

## 提案C：収益化

### C-1. Google AdSense【第一候補】
- 2026-08-01、「有用性の低いコンテンツ」で初回審査不承認。記事総数ではなく、公開面に混在していた旧簡易判例28件（約900〜1,300字）と簡易用語20件（約600〜900字）、目的別導線とサイト説明の弱さを主な改善対象と判断
- 対応済み：百選級改稿済み判例22件だけを判例一覧・新着・sitemap・Pagefindに掲載。旧簡易判例28件と簡易用語20件はURLを維持してnoindex化し、広告コードも停止。判決全文・検索・404等のnoindexページでも広告コードを停止。トップに目的別導線を追加し、Aboutを収録内容・記事の特徴・学習手順が分かる内容へ拡充
- 今後は旧簡易判例と用語ページを十分な独自解説へ改稿したものから品質ゲートへ戻す。再審査前後にSearch Consoleで新しいsitemapとnoindexの反映状況を確認する
- 法律ジャンルは広告単価が比較的高い
- 選択肢:
  - 案①: 先に申請だけ通し、掲載は控えめ（記事末尾のみ等）から始める
  - 案②: Search Console で検索流入が安定（目安: 数百PV/日）してから申請
- 申請自体は人間タスク（アカウント作成・サイト追加）。コード側（ads.txt・審査コード設置）はこちらで実装可能

### C-2. 書籍アフィリエイト（Amazonアソシエイト等）
- 各トピック末尾に「さらに学ぶための本」枠を設け、基本書・判例集を紹介する形なら学習サイトの体裁と両立し、「試験名を出さない」方針とも矛盾しない
- AdSenseより導入は軽いが、審査に実売実績が要る場合がある（もしもアフィリエイト経由が現実的）
