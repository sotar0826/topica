# ARTICLE_GUIDE.md — トピカ記事執筆規約

最終更新: 2026-07-05
適用範囲: 民法（応用編追加分）・コラム・今後の新科目（商法・民訴）のすべての新規記事

---

## 0. 大原則

1. **一次資料主義**: 条文は e-Gov 法令検索、判例は裁判所サイト（裁判例検索）を必ず参照する。
2. **確認できない判例・条文は書かない**: 年月日・出典を一次資料で照合できなかった判例は、
   内容に自信があっても記事に載せない。AI 執筆で最も危険なのは判例のハルシネーションである。
   ユーザーは他のAIで架空判例の生成を実際に経験しており（2026-07-05）、この規律は本サイトの
   信頼性の生命線である。**全判例を裁判所DB（courts.go.jp）で事件番号・出典・裁判要旨まで照合**
   してから執筆すること。照合手順は `SESSION_NOTES.md` の技術メモ参照（検索URL直叩き＋静的詳細ページ）。
3. **形式は既存記事に完全準拠**: フロントマターのスキーマ、コンポーネント記法
   （確認問題・「先に読んでおきたいページ」等）は、既存記事
   （例: `sakugo`＝錯誤）とコンテンツコレクションのスキーマ定義を必ず確認し、同一形式で書く。
   新しいフィールドや記法を勝手に発明しない。

## 1. 記事の種類とレベル定義

| 種類 | 想定読者 | 到達目標 |
|---|---|---|
| 基礎編 | 法学未修の初学者 | 専門用語ゼロ前提で読め、制度の趣旨と基本ルールが説明できる |
| 応用編 | 基礎編読了者 | 論述試験に対応。判例法理の展開・学説対立・限界事例まで |
| コラム | 基礎〜応用の間の読者 | 複数論点を横断する難所を深掘りする読み物。各コラムは独立 |

- 基礎編は既に51/51完成。新規に書くのは応用編（重要論点のみ）とコラム。
- 応用編は「基礎編の繰り返し＋α」にしない。基礎編との内容重複は最小限にし、
  基礎編へのリンクで代替する。

## 2. 記事構造（本文の型）

既存記事の構成を踏襲する:

1. **このページで学ぶこと** — 箇条書き3点前後。最後は「〜を説明できるようになる」というゴール形式
2. **制度の趣旨** — なぜこのルールがあるのか。原則→例外の順で
3. **解説** — 小見出し（H3）で分割。「条文を見てみよう」で条文引用から入る。
   要件→効果→第三者との関係、の順を基本とする
4. **具体例** — 日常的な場面に置き換えた事例
5. **よくある勘違い** — 初学者が混同しやすい点を明示的に潰す
6. **確認問題** — 既存のクイズ形式に準拠

> **注**: 旧「🤖 AIに質問する」セクションは 2026-07-05 に全ページから削除済み（AI色を薄くする方針）。
> 新規記事にも設置しない。

コラムは上記に縛られないが、「問題提起 → 判例・条文の展開 → 本編記事へのリンク」
の流れと、末尾の確認問題は維持する。

## 3. 文体・表記規約

- 文体: です・ます調。断定を避けない（「〜と考えられています」の乱用禁止。
  判例・通説が固まっている点は言い切る。争いがある点は「争いがある」と明示する）
- 専門用語: 初出時に必ず平易な言い換えを添える。例:「錯誤（さくご）＝思い違い」
- 条文表記: 科目内では法令名省略（「94条2項」）。他法令は法令名を付す（「借地借家法28条」）
- 判例表記: 「最判平成◯年◯月◯日」形式。大法廷は「最大判」。
  重要判例は民集等の出典を付す
- 強調: 太字は1段落に1〜2箇所まで。強調だらけの文章にしない
- 改正対応: 令和2年施行の債権法改正後の条文を基準とする。改正前の議論に触れる場合は
  「改正前は〜」と明示する
- 試験名: サイトのUI文言には「司法試験」「予備試験」等の試験名を出さない（2026-07-05 方針）。
  記事本文中でも試験名の使用は避け、「短答式」「論述」のような一般的表現にとどめる

## 4. 内部リンク規約

- 冒頭の「先に読んでおきたいページ」: 前提となる基礎編記事を1〜3本
- 本文中: 関連論点の初出箇所で本編記事へリンク
- 応用編: 対応する基礎編へ必ず相互リンク
- コラム: 扱った論点の本編記事（基礎編・応用編）へ必ずリンクを張る（回遊性の確保）

## 5. 確認問題の作り方

- 3〜5問。本文を読めば解ける水準（本文にない知識を要求しない）
- 「よくある勘違い」で挙げた混同点を必ず1問入れる
- 応用編は判例の結論を問う問題を含めてよい

## 6. 執筆プロセス（1記事あたり）

1. **構成設計**: 骨子（節立て＋引用予定の条文番号・判例リスト）を先に作る。
   **承認は `CONTENT_PLAN.md` の優先順位承認をもって包括承認とする**（2026-07-05 ユーザー指示。
   個別の骨子承認は不要。ユーザーが個別確認を求めた場合はその都度従う）
2. **一次資料照合**: 執筆時に e-Gov で条文の現行文言を、裁判所サイトで判例の
   年月日・結論を取得して照合する
3. **執筆**: 本規約と既存記事の形式に準拠して書く
4. **セルフレビュー**: 下記チェックリストで自己検査してから提出
5. **最終レビュー**: Sotaro が法的正確性を最終確認してから公開

## 7. セルフレビュー・チェックリスト

執筆後、以下を機械的に確認する:

- [ ] 引用したすべての条文番号を e-Gov の現行条文と照合した
- [ ] 引用したすべての判例の年月日・結論を一次資料で確認した（未確認の判例はゼロ）
- [ ] フロントマターが既存記事のスキーマと一致している
- [ ] 「先に読んでおきたいページ」と本文中の内部リンクを設定した
- [ ] 基礎編/応用編のレベル定義に合致している（応用編で基礎説明を繰り返していない）
- [ ] 表記規約（条文・判例・用語の書式）に準拠している
- [ ] 確認問題が本文の内容だけで解ける
- [ ] ビルドが通り、ローカルプレビューで表示崩れがない

## 8. 図表（図表コンポーネント完成後に適用）

汎用コンポーネント4種（三者関係図・時系列図・対比表・フローチャート）の完成後は:
- 三者関係が登場する論点では三者関係図を原則入れる
- 「取消し前後」「対抗の前後」など時間軸が争点の論点では時系列図を入れる
- 制度比較（錯誤vs詐欺 等）は対比表にする
- 図は1記事3点まで。図で説明できることを長文で重複説明しない
